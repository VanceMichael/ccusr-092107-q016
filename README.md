# 良种成果转化接力

保存种质材料、育种试验、审定许可和市场推广的连续关系，把企业需求前置到育种材料阶段，并保证合作企业只能查看获准范围。

## 要解决的问题

- 企业过去在品种审定后才接触成果，试种性状常与市场需求错位；配套栽培技术和区域适配资料散落在不同团队。
- 平台需要在企业提前参与的同时，防止其窥见其他团队的未公开材料。
- 平台还要处理试验地排期、阴性试验、联合育种、许可冲突、品种更名和推广反馈。
- 最终要能回答两件事：**市场信息改变了哪次育种决策**；**销售的种子是否来自获准（已审定、已许可）版本**。

## 领域资料

- `contracts/context.schema.json`：基础资料格式（领域标识、版本、业务事实）。
- `contracts/domain-pack.schema.json`：完整领域资料包契约，覆盖团队、种质谱系、市场信号、育种决策、试验地与排期、田间试验、配套栽培技术、品种（名称沿革/版本）、审定登记、联合育种协议、知识产权、许可、企业授权、推广反馈、销售批次。
- `fixtures/context.json`：最小样例。
- `fixtures/domain-pack.json`：贯穿全流程的虚构样例（编号与主体均为虚构，无真实个人信息）。

## 代码模块（纯 ESM，无第三方依赖）

| 模块 | 职责 |
| --- | --- |
| `src/context.js` | 读取最小领域资料 |
| `src/pack.js` | 资料包解析、引用完整性与跨字段校验、索引 |
| `src/lineage.js` | 材料祖先链、版本谱系（含名称沿革、审定区域、配套技术）、证据时间线 |
| `src/scheduling.js` | 试验地时段排期，重叠申请驳回；被驳回申请不占用时段 |
| `src/licensing.js` | 共有人书面同意核验、独占/排他许可冲突、许可受理评估、销售批次溯源 |
| `src/access.js` | 企业授权视图裁剪；防止授权清单暴露合作谱系外的未公开材料 |
| `src/market-trace.js` | 市场信号→决策→世代→审定版本的解释，以及推广反馈闭环 |

### 样例中演示的关键规则

- **需求前置**：企业在 BC1F1 世代提出直播稻需求（`ms-01`），改变定向选择（`d-03`）与联合创制（`d-04`）决策。
- **排期冲突**：`bk-02` 与已排定的 `bk-01` 在同一地块时段重叠，平台驳回并记录原因。
- **负面试验**：南繁耐冷筛选阴性（`ft-neg-01`）导致姊妹系 `g-006` 被淘汰（`d-05`），不进入报审，但记录留存谱系。
- **联合育种与同意**：联合成果的品种权由协议各方共有；对外许可须全体共有人书面同意，`lic-02` 因共有人未同意而处于争议。
- **许可冲突**：`vv-001-0` 在黄淮已有独占许可 `lic-01`，同区域同期限的新许可申请会被驳回。
- **品种更名**：`苏仓粳1号` 更名为 `仓粳优1号`，株系名、原审定名与更名记录构成连续名称谱系。
- **推广反馈闭环**：推广端高温结实率差（`pf-01`）回流为市场信号 `ms-02`，驱动耐热改良决策 `d-06`，形成已扩区审定的 `vv-001-1`。
- **销售溯源**：`sb-ok`/`sb-ok2` 可证明来自获准版本；过期许可（`sb-bad-expired`）、越区（`sb-bad-region`）、销售未审定版本（`sb-bad-version`）均判不合规。
- **授权隔离**：禾丰种业（联合育种方）可见合作谱系内的材料与世代；绿仓种业（审定后接触）只看到品种公开版本，看不到任何育种材料；其他团队未公开亲本（如 `g-001`、`g-008`）对任何企业不可见。
